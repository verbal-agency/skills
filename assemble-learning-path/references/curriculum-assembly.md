# Curriculum assembly

## Ordering constraints

Honor hard prerequisites, then optimize for motivation, early usefulness,
cognitive load, coherent context, and opportunities to retrieve prior material.
Documentation order, graph traversal order, and curriculum order are rarely
identical.

## Module contract

Give each module one primary capability and a small number of supporting
concepts. Record entry evidence, the motivating problem, learning units,
practice, closure evidence, remediation, review timing, and the next capability
unlocked. Split modules that cannot be closed with one coherent evidence gate.

## Instructional arcs

Prefer an arc such as:

```text
authentic problem → minimal vocabulary → working model → guided success
→ alternatives and tradeoffs → failure and diagnosis → independent integration
```

For conceptual domains, substitute cases, proofs, or interpretations for labs
while preserving progression from model to independent use.

## Spiraling and interleaving

Revisit a concept only when the next encounter adds a new context, cognitive
level, or integration. Interleave confusable alternatives after each has a
minimal working model. Avoid random alternation that destroys coherence.

## Adaptation

Create branches from evidence, not learning-style labels. Permit prerequisite
exemption only with direct evidence. Route factual gaps, faulty models,
procedure failures, and transfer failures to different remediation activities.

## Feasibility

Estimate active effort separately from elapsed spacing. Check accounts,
hardware, software, data, costs, safety, and accessibility. Provide an explicit
reduced-environment route when it can still produce valid evidence; otherwise
state the dependency.

## Coverage audit

For every required capability, identify where it is introduced, practiced,
assessed, revisited, and integrated. For every module, identify the required
capability it advances. Remove decorative material with no justified mapping.
