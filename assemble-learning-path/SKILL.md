# Assemble Learning Path

Turn reusable package components into a curriculum. Treat the concept graph as
a constraint, not as the finished teaching order.

## Required inputs

Read the package scope, capability inventory, graph, concept units, exercise
metadata, target learner profile, available time, and required completion
evidence. Read [references/curriculum-assembly.md](references/curriculum-assembly.md)
before building or materially revising a path.

## Workflow

1. **Write the curriculum contract.** State audience, starting assumptions,
   target capabilities, time and environment constraints, non-goals, and final
   evidence.
2. **Run a diagnostic gate.** Use existing evidence or select diagnostic items
   to decide which prerequisites require instruction, review, or exemption.
3. **Select the smallest sufficient subgraph.** Include all hard prerequisites
   and material contrasts. Exclude interesting concepts that do not advance the
   outcome.
4. **Choose an instructional arc.** Begin with an authentic motivating problem,
   teach the minimum vocabulary and model needed for an early success, then add
   depth, alternatives, failure, diagnosis, and independent integration.
5. **Build modules.** Give each module one primary capability, prerequisites,
   concept units, practice, closure evidence, and a downstream unlock.
6. **Manage cognitive load.** Limit simultaneous new abstractions. Place
   summaries or consolidation where dependency fan-in is high.
7. **Spiral and interleave.** Revisit important concepts at increasing depth
   and place confusable alternatives near enough to practice discrimination.
8. **Use fading support.** Progress from worked examples to completion tasks,
   independent work, transfer, troubleshooting, design, and defense as the goal
   requires.
9. **Place evidence gates.** Require direct evidence before advancing across a
   dependency boundary. Add remediation routes for likely failure patterns.
10. **Add cumulative work.** Use a capstone or authentic performance task that
    integrates the target capabilities without introducing an unmodeled domain.
11. **Check coverage and feasibility.** Map every target capability to teaching,
    practice, and assessment; estimate effort; check tool, cost, safety, and
    access constraints.
12. **Write the curriculum.** Copy and adapt
    [assets/curriculum-template.yaml](assets/curriculum-template.yaml). Set the
    package stage to `assembled` only after all required components and mappings
    are present.

## Assembly rules

- Do not teach alphabetically or mirror documentation navigation by default.
- Do not require advanced details before the learner has a useful working model.
- Do not repeat identical explanations; revisit through a new context or level.
- Keep certification coverage distinct from real-world capability evidence.
- Provide optional branches rather than forcing every learner through every
  adjacent subject.

Report the learning arc, capability coverage, estimated effort, diagnostic and
remediation branches, final evidence, and remaining package gaps.
